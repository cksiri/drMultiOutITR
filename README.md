# drMultiOutITR

**Version 0.1.0.**

`drMultiOutITR` provides **doubly robust, individualized treatment
rankings** for observational studies involving two or more treatments and
mixed-type responses (continuous, ordinal, binary, and censored survival).
Its main functions are `fit_dr_itr()` and `predict()`.

The package's recommendations are **estimated treatment rankings**, not
proven clinical benefits or independent estimates of policy value. Results
require defensible confounding, positivity, outcome-model, and censoring
assumptions.

## Installation

**From GitHub** (once the repository has been published):

```r
install.packages("remotes")
remotes::install_github("cksiri/drMultiOutITR")
library(drMultiOutITR)
```

Repository: [https://github.com/cksiri/drMultiOutITR](https://github.com/cksiri/drMultiOutITR).
This link and command become usable after the GitHub repository is
created and made accessible. The package is **not claimed to be on CRAN**.

**From a downloaded source folder** (also works before GitHub publication):

```r
install.packages("remotes")
remotes::install_local("path/to/drMultiOutITR", dependencies = TRUE,
                      build_vignettes = TRUE)
library(drMultiOutITR)
```

Replace `path/to/drMultiOutITR` with the location of the extracted package
folder. The package is currently provided as source code; these commands do
not imply that it is available on CRAN. Optional survival random-forest
analyses also require `randomForestSRC` compatible with your R installation.

## Start here: one complete toy example

The recommended first example uses **three treatments** (`Care_A`, `Care_B`,
`Care_C`) and **three different responses**:

| Outcome | Data type | Preferred direction |
|---|---|---|
| Length of stay | Continuous | Shorter |
| Wellbeing | Ordinal | Higher category |
| Survival | Right-censored | Higher survival probability |

The data are **generated by the example**. No participant records are needed.

1. Install the package using the instructions above. Alternatively, if you
   are developing from the source folder, use `devtools::load_all()`.
2. Install `ranger` and `survival` if not already available:

   ```r
   install.packages(c("ranger", "survival"))
   ```

3. Run the complete worked example:

   ```r
   library(drMultiOutITR)
   source(system.file("examples", "three_treatment_mixed_outcomes.R",
                      package = "drMultiOutITR"))
   ```

   When working in the **source** folder after `devtools::load_all()`, use
   `source("inst/examples/three_treatment_mixed_outcomes.R")` instead.

The example shows how to construct an outcome list, fit a rule, rank new
profiles, change outcome weights **without refitting**, and save/reload the
fitted rule. The `optimal_ranking` string records the **rank of each treatment**
in `fit$treatments` order (1 = most preferred), while `best_treatment` gives
the named first choice. The example also prints a readable best-to-worst order.
Tree counts are intentionally small for teaching, not for research-quality
inference.

The `theta_hat` column in the prediction summaries is the estimated
conditional outcome summary for a given profile and treatment: a quantile for
continuous outcomes, a category-threshold probability for ordinal outcomes,
a favorable-event probability for binary outcomes, or a survival probability
at the indicated follow-up time. These values are not observed outcomes or
individual treatment effects.

For explanations alongside each step, open:

```r
vignette("getting-started", package = "drMultiOutITR")
```

## A little RHC example (optional)

A separate guide shows how the same functions can be applied to the original

It is optional because prepared RHC analysis files are **not distributed** in

```r

```

This reduced-settings demonstration is **not** the manuscript's full
outer-five-fold RHC evaluation, an independent policy-value analysis, or a
clinical decision tool. Neither RHC nor DATOS participant records are bundled.

## Using your own study data

- Organize one row per individual. Include their **observed treatment**, all
  pretreatment covariates, and the outcome variables needed for training.
- Use at least two treatment levels; ensure sufficient observations per arm
  for the chosen nuisance folds and check treatment overlap.
- Define each outcome type and what counts as favorable. For ordinal outcomes,
  give the true category order. For survival, define `time`, `status`
  (`1` = observed event, `0` = censored), and the follow-up times of interest.
- Handle missing values and uncommon categorical levels before fitting;
  new prediction profiles need only the same complete baseline covariates.
- Call `fit_dr_itr()` to fit, then `predict()` to rank options for new profiles.
  You can pass alternative named `weights` to `predict()`.
- Assess causal assumptions and estimator diagnostics before substantive
  interpretation. The `censoring="pooled_km"` option requires censoring
  independent of treatment and covariates; choose assumptions appropriate to
  the study. Fixed propensity truncation and experimental survival-response
  rounding can affect estimates. Rounding is **off by default**.

See `?fit_dr_itr` and `?predict.dr_itr` for the optional controls. The
package does not automatically solve unmeasured confounding, censoring-model
misspecification, or independent policy-value evaluation.

## Data privacy and scientific interpretation

No RHC or DATOS patient-level files, fitted models, or research outputs are
included. Do not publish fitted models or individual predictions from private
studies without authorization. The package provides model-based estimates and
rankings; causal interpretation requires the study assumptions described above.
